Style

Convenciones de escritura. El objetivo es uniformidad: todo archivo se lee igual que el de al lado.

01 Regiones

RegiónContenido
FIELDSSerializado — lo que ve el inspector.
LIFETIMEMensajes de Unity · ciclo Hook / Handle / Unhook.
APISuperficie pública.
MISCSoporte privado.
  • Orden fijo; la región vacía se omite; línea en blanco tras #region y antes de #endregion.
  • Variables no serializadas: junto a la función que las usa, no en un bloque superior.
  • Tipos nested al final del archivo: enums públicos, clases privadas, foldouts serializables.

02 Prácticas

TemaConvención
InspectorAtributos nativos ([Header], [Tooltip], [Range]). El agrupado visual lo aporta Charm, no Odin.
APIEl consumidor habla con la clase pública; las nested privadas operan por dentro. Se exponen métodos, no estructuras internas.
Config agrupadaClase nested [Serializable] como campo (foldout) — no un Addon.
Estado compartidoFlags efímeros entre addons → Values. Referencias directas → se cachean en Hook, nunca se resuelven por frame.

03 Workflow

TemaRegla
CommitsSolo el autor, vía GitHub Desktop. En inglés, cortos: qué y por qué.
Ramasgenesis desarrollo · release estable con tags v0.x.y.
HigieneConfiguración de agentes fuera del repo vía .git/info/exclude — nunca .gitignore.

04 Documentación

  • Se documenta lo terminado; lo dispara el autor (Design · Filosofía).
  • Una página por tema en docs/res/, compartiendo css/quark.css y js/quark.js.
  • Toda página o sección nueva se registra en el índice del buscador (res/js/search.js).
  • Alcance actual: diseño y recursos. La referencia de código entra cuando la API esté estable.
